InfraAdvisor accepts image and audio attachments without placing media bytes in the query JSON or conversation history. Azure OpenAI processes the media; Datadog retains operational metadata rather than filenames, signed URLs, transcripts, descriptions, or bytes.

## The cascade

```text
authenticated upload → private Blob container → read-only attachment reference
                                                  │
query + reference ──validate───────────────────────┤
                                                  ├─ audio → Whisper → effective text query
                                                  └─ image → vision-capable model input
                                                               │
                                                     normal agent workflow
```

Audio becomes text before routing, retrieval, and tool selection. An image is supplied to the model path for the current turn. Stored conversation history does not re-download or reprocess earlier attachments.

## Upload contract

Both backends expose an authenticated, rate-limited media upload endpoint. It accepts an allowlist of JPEG, PNG, WebP, WebM, WAV, MPEG audio, and Ogg media, with a 10 MiB maximum.

Blob names contain only the media kind and a random UUID. Original filenames and chat session IDs are deliberately excluded. The returned reference contains the kind, MIME type, byte count, and an expiring read-only Blob URL.

## Treat every reference as untrusted

Before restoring memory or calling a model, each backend validates that the reference:

- uses HTTPS and the configured Blob host and container;
- follows the generated `<kind>/<UUID>` path shape;
- has matching kind and allowlisted MIME type;
- declares a bounded positive size;
- has a blob-scoped, read-only SAS contract;
- does not target loopback, link-local, private, metadata, or foreign hosts.

Audio downloads disable redirects, cap the response at 10 MiB, and require the bytes read to match the validated reference. These controls turn a user-supplied URL from a general server-side fetch into one narrow storage capability.

## Telemetry boundary

Custom spans can retain modality, allowlisted MIME type, byte count, duration, status, model, routed domain, and trace correlation. They must not retain the signed URL, filename, media, prompt, transcript, vision description, response, or session identifier.

Python annotates explicit transcription and vision steps with bounded metadata. .NET disables sensitive content in its Microsoft.Extensions.AI and agent-framework telemetry decorators. Its automatic HTTP instrumentation excludes Blob media downloads so signed query parameters cannot appear on client spans; a parent manual activity preserves duration and status.

<Aside type="note">
This boundary intentionally gives up inline media and transcript inspection in Datadog. The remaining signals still answer whether upload, validation, transcription, routing, tools, or the model caused a failure.
</Aside>

## Investigate one attachment

<ObservationChecklist>

- Upload an allowed test file and confirm its generated object name contains no original filename or session ID.
- Submit the returned reference and locate the end-to-end trace.
- For audio, confirm transcription precedes routing; for images, confirm the vision path appears in the expected model step.
- Verify size, MIME type, duration, and status metadata are present.
- Search telemetry for sentinel filename, SAS signature, transcript, and media marker values; each must be absent.
- Try a foreign host, writable SAS, wrong MIME/kind pair, and redirect in tests; each must fail before model invocation.

</ObservationChecklist>
