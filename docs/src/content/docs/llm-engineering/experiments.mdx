Production observability asks what happened. An experiment asks whether one controlled version performs better than another on the same examples. InfraAdvisor needs the second loop before prompt, model, or tool-description changes can be evaluated with more than a few manual requests.

## The learning loop

```text
Production traces → human review → curated dataset
                                      │
Candidate change → experiment run ────┤
Baseline version → experiment run ────┘
                                      │
                         compare results and inspect regressions
```

The comparison—not a single average score—is the decision artifact. A candidate can improve the mean while breaking an important edge case.

## Minimum useful dataset

Build a small, diverse set before automating a large one. Include:

- representative questions from each supported domain;
- cases that require one tool and cases that require a tool sequence;
- known routing and citation failures;
- short or ambiguous requests where a clarifying response is correct;
- examples with human-reviewed expected behavior.

Version the dataset and rubric together. If either changes, results from earlier runs may no longer be directly comparable.

## Proposed adoption sequence

1. Use an annotation queue to create trusted examples.
2. Define a stable invocation boundary for both backends.
3. Capture the prompt/model/service version with every run.
4. Run deterministic evaluators first, then calibrated judges.
5. Compare candidate and baseline per example.
6. Review regressions before adding any CI threshold.
7. Only gate merges after repeated runs show the measurements are stable.

Datadog's Experiments APIs and UI are evolving. Use the current [Experiments documentation](https://docs.datadoghq.com/llm_observability/improve/experiments/) when implementing the runner rather than copying transient product limits into this course.

<Aside type="note">
Traffic volume is not the readiness criterion. InfraAdvisor is ready when it has representative examples, trustworthy labels, reproducible invocation, and evaluation signals that the team understands.
</Aside>

Start with [Annotation queues](../evaluations/annotation-queues/) and use the [Export API](../evaluations/export-api/) only if the dataset workflow requires offline span retrieval.
