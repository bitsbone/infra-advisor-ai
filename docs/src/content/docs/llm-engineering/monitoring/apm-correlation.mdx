Agent Observability explains agent-specific work. Correlation explains the application and infrastructure work surrounding it. The contract is simple: preserve trace context and emit the identifiers or database attributes Datadog needs to join each signal.

## Correlate logs to the active span

Datadog expects structured log fields named `dd.trace_id` and `dd.span_id`.

<Tabs syncKey="lang">
  <TabItem label="Python — ddtrace">

`DD_LOGS_INJECTION=true` adds the active Datadog context to standard Python logging. The application still controls the useful message and safe business fields:

```python
logger.info("query completed", extra={"query.domain": domain})
```

Use JSON output so the Agent can parse the injected identifiers as fields rather than text.

  </TabItem>
  <TabItem label=".NET — OpenTelemetry">

The .NET services use a Serilog enricher that reads `Activity.Current` and writes Datadog-compatible decimal identifiers:

```csharp
var activity = Activity.Current;
if (activity is not null)
{
    logEvent.AddPropertyIfAbsent(
        new LogEventProperty("dd.trace_id", new ScalarValue(ToDatadogTraceId(activity.TraceId))));
    logEvent.AddPropertyIfAbsent(
        new LogEventProperty("dd.span_id", new ScalarValue(ToDatadogSpanId(activity.SpanId))));
}
```

The conversion uses the lower 64 bits of the W3C trace ID in decimal, matching Datadog log-correlation expectations while the complete trace remains 128-bit.

  </TabItem>
</Tabs>

## Correlate database work

<Tabs syncKey="lang">
  <TabItem label="Python — ddtrace">

Python uses supported database integrations and full DBM propagation:

```yaml
DD_DBM_PROPAGATION_MODE: "full"
DD_TRACE_SQLALCHEMY_ENABLED: "true"
DD_TRACE_ASYNCPG_ENABLED: "true"
```

The database integration injects correlation information into supported statements so DBM can connect query samples to the originating trace.

  </TabItem>
  <TabItem label=".NET — OpenTelemetry">

The .NET path is attribute-based:

1. `Npgsql.OpenTelemetry` emits database spans and semantic attributes.
2. The collector's `attributes/dbm` processor adds `span.type=sql` to matching spans.
3. The PostgreSQL Datadog integration runs with DBM enabled and a stable `reported_hostname`.

This avoids rewriting SQL while retaining statement, timing, and host evidence for correlation.

  </TabItem>
</Tabs>

## Verify from one trace

Open a tool-using agent trace and follow each available pivot:

<ObservationChecklist>
  <ul>
    <li>The Logs view contains messages emitted during the active request, not merely the same time range.</li>
    <li>A database operation links to the matching DBM query sample when SQL was involved.</li>
    <li>RUM opens the browser session that initiated the request.</li>
    <li>Infrastructure context identifies the pod or service handling the slow operation.</li>
  </ul>
</ObservationChecklist>

An empty correlation view is evidence of a broken join, not proof that nothing happened. Check the field names, log source/service tags, active trace context, collector processors, and database hostname before changing the agent instrumentation.
