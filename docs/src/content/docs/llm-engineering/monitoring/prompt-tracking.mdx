When a prompt changes, date ranges are a weak comparison boundary: deployments overlap, rollbacks happen, and unrelated code may ship at the same time. A content-derived version lets traces and evaluations identify the prompt definition that actually ran.

## The privacy-preserving pattern

InfraAdvisor hashes the system prompt and exports only the version:

```csharp
static string ShortContentHash(string text) =>
    Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(text)))
        .Substring(0, 8)
        .ToLowerInvariant();

var promptVersion = "v1-" + ShortContentHash(AgentSystemPrompt);

if (activity.OperationName is "invoke_agent" or "chat")
    activity.SetTag("prompt.version", promptVersion);
```

The value changes when the prompt content changes, but the template itself is not copied into a custom span attribute. This preserves correlation without expanding the telemetry content boundary.

## What is implemented

- The .NET backend stamps `prompt.version` on `invoke_agent` and `chat` activities.
- External evaluation submissions include a prompt-version tag, although that tag currently comes from the `PROMPT_VERSION` environment value rather than the content-derived hash. Aligning those sources remains necessary for exact joins.
- The Python backend does not yet emit an equivalent content-derived prompt-version tag.

Because coverage and version sources differ, prompt comparisons across both backends are not yet authoritative.

## Use the version to answer a bounded question

Pair the version with a signal that represents the outcome you care about:

- Evaluation score by `prompt.version`
- Tool-selection rate by `prompt.version`
- Token usage or cost by `prompt.version`
- Error and latency distribution by `prompt.version`

Do not interpret a correlation as causation without controlling for model, backend, traffic mix, and tool availability. For deliberate regression tests, use an offline [experiment](../../experiments/) with a stable dataset.
