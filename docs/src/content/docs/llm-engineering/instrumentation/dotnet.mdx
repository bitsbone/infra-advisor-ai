The .NET backend stays OpenTelemetry-native. Microsoft AI and MCP libraries create activities, the application adds missing product meaning, and the Datadog Agent collector receives OTLP data for Agent Observability.

**Source of truth:** `services/agent-api-dotnet/Observability/TelemetrySetup.cs` and `services/mcp-server-dotnet/Observability/TelemetrySetup.cs`

<Aside type="caution">
**Use one tracing pipeline.** InfraAdvisor does not run the Datadog .NET tracer beside the OpenTelemetry SDK. Two tracers can interpret propagation differently and split one request into separate trace trees.
</Aside>

## Follow responsibility through the pipeline

```text
Microsoft Agents / M.E.AI / MCP
        │ create GenAI activities
        ▼
OpenTelemetry SDK
        │ selects sources, resources, sampling, exporters
        ▼
Datadog Agent OTel collector
        │ processes resources and forwards OTLP
        ▼
Agent Observability + APM
```

| Source | What it contributes |
|---|---|
| `Experimental.Microsoft.Extensions.AI` | Chat, embedding, and tool-execution activities |
| Application `ActivitySource` | Agent orchestration and project-specific tasks |
| `Experimental.ModelContextProtocol` | MCP client and server operations |
| ASP.NET Core and HTTP instrumentation | Request boundaries and downstream calls |
| Npgsql instrumentation | Database work for APM and DBM correlation |

Datadog classifies supported GenAI operations from their semantic attributes. Application-specific `task` or `retrieval` work may need an explicit `dd.llmobs.span.kind` attribute.

## Register only the sources you need

The essential tracing configuration is intentionally small:

```csharp
builder.Services.AddOpenTelemetry()
    .ConfigureResource(resource => resource
        .AddService(serviceName)
        .AddAttributes(new Dictionary<string, object>
        {
            ["deployment.environment"] = ddEnv,
            ["service.version"] = ddVersion,
            ["source"] = "otel",
        }))
    .WithTracing(tracing => tracing
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation()
        .AddNpgsql()
        .AddSource("Experimental.Microsoft.Extensions.AI")
        .AddSource("Experimental.ModelContextProtocol")
        .AddSource(TelemetrySetup.ActivitySourceName)
        .AddOtlpExporter());
```

Registering a source only tells OpenTelemetry to listen. The AI libraries must also be configured to emit activities with `.UseOpenTelemetry(...)`.

## Add meaning the libraries cannot infer

Wrap deterministic application work with the project activity source:

```csharp
using var activity = ActivitySource.StartActivity("classify_domain");
activity?.SetTag("dd.llmobs.span.kind", "task");
activity?.SetTag("gen_ai.operation.name", "classify_domain");

var domain = await ClassifyDomain(query);
activity?.SetTag("query.domain", domain);
```

The explicit span identifies the operation and its safe outcome. It does not need to copy the full query into a custom attribute when the child model activity already carries permitted content.

## Decide whether content should be captured

Microsoft.Extensions.AI can emit prompt and completion content when sensitive-data capture is enabled. Without it, timing, tokens, model details, and operation structure remain observable while message bodies are omitted.

Choose that setting from the service's data policy, not from a desire to maximize fields. Never attach SAS URLs, raw media, credentials, or unbounded provider responses as custom activity attributes.

## Diagnose the missing boundary

| Symptom | Check first |
|---|---|
| AI operations missing | Library emission and matching `.AddSource(...)` registration |
| Span reaches APM without Agent classification | GenAI operation name and semantic attributes |
| Trace splits across services | W3C propagation and accidental second tracer |
| Prompt content absent | Sensitive-data capture policy and library configuration |
| OTLP export fails | Endpoint protocol, `/v1/traces` handling, and collector ports |
| MCP server absent | Server-side source registration and session routing |

Continue to [MCP client instrumentation](../../monitoring/mcp-clients/) for the service boundary or [APM correlation](../../monitoring/apm-correlation/) for logs and database work.
