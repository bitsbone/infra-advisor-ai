A custom LLM-as-a-judge evaluation expresses a rubric in natural language and lets Datadog run it over selected spans, traces, or sessions. It is useful when the criterion is semantic and the evidence already exists in Agent Observability. InfraAdvisor does not store a Datadog custom-judge configuration in this repository; the page explains how to decide whether to adopt one.

## Make the path decision first

| Need | Better path |
|---|---|
| Rapidly iterate a helpfulness or tone rubric | Datadog custom judge |
| Inspect private application state or uncaptured tool results | External evaluator |
| Enforce exact format, routing, or ordering | Deterministic external evaluator |
| Establish ground truth for an ambiguous criterion | Annotation queue |
| Keep rubric changes behind code review | External evaluator |

InfraAdvisor's current relevance and groundedness judges live in the .NET service. A Datadog custom judge would be a second implementation, so adopt one to answer a distinct learning question—not simply to duplicate an existing score.

## A useful first experiment

Choose one criterion with clear endpoints, such as “Does the answer give an actionable next step?” Write a rubric that defines pass and fail, then run it against a deliberately mixed sample. Inspect the judge's reasoning and revise the rubric where humans disagree.

Datadog supports different evaluation scopes. Span scope isolates one operation; trace scope can reason across an agent workflow; session scope can assess a multi-turn interaction. Select the smallest scope containing the evidence your rubric requires. See the current [custom LLM-as-a-judge documentation](https://docs.datadoghq.com/llm_observability/configure/evaluations/llm_as_a_judge_evaluations/) for configuration and compatibility details.

## Calibrate before monitoring

1. Define the rubric and examples outside the prompt.
2. Have humans label a small, diverse sample without seeing the judge result.
3. Compare disagreements and revise unclear criteria.
4. Repeat until the score is stable enough for its intended use.
5. Monitor trends before treating one result as a release gate.

<Aside type="caution">
An LLM judge is another probabilistic model call. Its confident reasoning is not proof that the score is correct. Preserve human-reviewed examples and recheck them when the rubric, provider, or model changes.
</Aside>

Use [Annotation queues](../annotation-queues/) to build the human comparison set.
