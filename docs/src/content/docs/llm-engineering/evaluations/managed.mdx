Managed evaluations are Datadog-provided checks that run against eligible Agent Observability spans after ingestion. They are the fastest way to explore common quality and safety signals before building project-specific evaluator code.

## Use them for broad questions

Managed checks are a good first layer for questions shared by many LLM applications, such as whether a response changes language unexpectedly. The available catalog and compatibility requirements evolve, so use the current [Datadog managed evaluations guide](https://docs.datadoghq.com/llm_observability/evaluations/managed_evaluations/) as the source of truth rather than treating a copied list here as permanent.

InfraAdvisor-specific rules belong elsewhere:

- Use a deterministic external evaluator for required citations or MCP tool ordering.
- Use a custom judge for a semantic rubric unique to the product.
- Use human annotation when the criterion is ambiguous or still being defined.

## Adoption loop

1. Confirm the target backend emits eligible spans with useful input and output content under the intended privacy policy.
2. Enable one evaluation for one ML application in Datadog.
3. Generate a small set of obvious pass and fail examples.
4. Inspect the result and its source span before creating a monitor.
5. Record the selected evaluation, scope, and owner in project operations documentation.

<ObservationChecklist>

- The evaluation appears on the expected span kind.
- Both successful and deliberately poor examples receive plausible results.
- The score arrives asynchronously without affecting request latency.
- The team knows which backend and ML application are covered.
- Any alert uses observed baseline behavior, not an arbitrary threshold.

</ObservationChecklist>
