The Agent Observability Export API retrieves span data for offline evaluation, dataset construction, or analysis. InfraAdvisor does not currently call it; this page defines the boundary for a future consumer.

## Use a separate workload

Run exports from a scheduled job, analysis environment, or dataset pipeline—not from the request-serving agent. Reading data requires an application key in addition to an API key, and that read credential should not be added to the agent container merely for convenience.

```text
Agent services ──write telemetry──▶ Datadog
                                      │
Offline export job ◀──read spans──────┘
         │
         └──▶ evaluation, dataset, or analysis output
```

## Design the consumer around pagination

The current API supports filtering by fields such as trace ID, span ID, span kind, span name, ML application, tags, and time range. Results are paginated with a cursor and subject to response-size limits. Use the official [Export API reference](https://docs.datadoghq.com/llm_observability/investigate/export_api/) for the current endpoint and parameters.

A robust consumer should:

1. request a bounded time range;
2. filter to the smallest useful cohort;
3. persist the next cursor only after a page is processed;
4. deduplicate by stable span identity;
5. retry rate limits and transient failures with backoff;
6. record an export watermark and audit metadata;
7. apply the same retention and redaction rules as the source telemetry.

## Preserve meaning outside Datadog

Exporting JSON does not create a useful dataset by itself. Retain the fields needed to interpret an example: ML application, service version, prompt version when available, span kind, input/output capture state, evaluator definitions, and the relationship between parent and child spans.

<Aside type="caution">
Exported span content can include prompts, responses, and tool data. Moving it to a notebook or object store creates another governed copy. Define access, encryption, retention, and deletion behavior before scheduling the export.
</Aside>
