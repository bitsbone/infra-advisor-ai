This guide uses InfraAdvisor as a working laboratory for Datadog Agent Observability. The goal is not to reproduce Datadog's reference documentation. It is to connect product capabilities to concrete implementation choices, application behavior, and telemetry you can inspect.

InfraAdvisor deliberately runs two agent backends:

- **Python** uses LangChain, LangGraph, `ddtrace.auto`, and explicit `LLMObs` spans.
- **.NET** uses Microsoft Agents Framework, Microsoft.Extensions.AI, OpenTelemetry, and OTLP export through the Datadog Agent.

That contrast is useful for instrumentation topics. Other features use the structure that best supports their own question: a guided exercise, an investigation, a design explanation, a reference, or an evolving experiment.

## Follow the Datadog learning loop

### Instrument

Create the spans and attributes that describe the agent's work. Start with automatic coverage, then add explicit meaning where frameworks cannot infer orchestration, business context, privacy decisions, or product-specific operations.

### Investigate

Use traces, metrics, sessions, and APM correlation to explain behavior. The important outcome is not merely that data arrived; it is that the data answers a debugging or operational question.

### Improve

Attach evaluations and feedback so correctness, safety, and usefulness become observable alongside latency, cost, and errors. Use experiments when a change needs evidence before it reaches production.

### Configure and protect

Operate evaluations, prompts, automation, capture policies, and access controls deliberately. Configuration is part of the system's behavior, not an appendix to instrumentation.

## Read feature maturity honestly

Pages may be labeled **Verified**, **Experimental**, **Partial**, **Planned**, or **Deprecated**. A status describes this repository's implementation and verification state, not the availability of the Datadog product itself.

- **Verified** means the documented project behavior has been exercised successfully.
- **Experimental** means the implementation exists but the pattern is still being evaluated.
- **Partial** means only some backends, clients, or expected signals are complete.
- **Planned** means the page records a researched direction, not shipped behavior.
- **Deprecated** preserves a comparison or migration path that should no longer be copied.
