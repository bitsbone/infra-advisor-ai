Azure Data Factory refreshes public infrastructure data, preserves source snapshots in private Blob Storage, and builds documents for Azure AI Search. The search index is a serving layer; the staged source data makes each run explainable and reproducible. This replaced a self-hosted Airflow-on-AKS deployment — see the [migration notes](/agent-guides/airflow-to-adf-migration/) for why and what changed.

## Shared ingestion pattern

<FlowExplorer client:visible title="Inspect the pipeline boundary" flows={pipelineFlows} />

Each pipeline is two Azure Function Activities: `fetch-and-store-<domain>` fetches and validates records, then `index-search-shared` (one shared activity reused by every domain) chunks, embeds, and upserts them into Azure AI Search. Blob paths pass between activities as plain pipeline parameters — Function Activity outputs have no equivalent to Airflow XCom's metadata-DB size limit, so the manifest/checksum verification layer the old DAGs needed doesn't exist here.

## Enabled source families

| Pipeline | Cadence | Serving domain |
|---|---|---|
| `pl-fema-refresh` | Daily | environmental |
| `pl-nbi-refresh` | Weekly | transportation |
| `pl-eia-refresh` | Weekly | energy |
| `pl-samgov-awards-refresh` | Weekly | business development |
| `pl-census-market-intelligence-refresh` | Monthly | business development |
| `pl-public-docs-ingestion` | Weekly | knowledge corpus |

Two source families from the original Airflow deployment were retired during the migration rather than ported, since neither carries its weight in a demo environment — see the [migration notes](/agent-guides/airflow-to-adf-migration/) for what this means for their previously-indexed data:

- **TWDB water plan refresh** (`water` domain) — the most complex of the original DAGs (zip-bomb/path-traversal validation, fan-in/fan-out graph); has no ADF pipeline.
- **Synthetic knowledge-base initialization** — a one-time bootstrap (~80 sequential LLM calls generating synthetic docs), already run at least once; has no ADF pipeline or other automated regeneration path.

## Reproducible Functions runtime

Every pipeline's Function Activities run inside one Azure Functions app (`services/adf-functions/`, Python 3.12, Linux Consumption plan) deployed via `func azure functionapp publish` — a single deploy updates every domain's fetch and indexing logic at once, the same "one image, many jobs" model the Airflow deployment used.

Verify locally before publishing:

```bash
cd services/adf-functions
uv run pytest
```

## Datadog evidence

Datadog's Data Jobs Monitoring for Azure Data Factory (a pull-based Azure integration, not OpenLineage) tracks pipeline and activity run status, duration, and failure rate — see [`ops/azure/README.md`](https://github.com/bitsbone/infra-advisor-ai/blob/main/ops/azure/README.md) for the one-time setup. Function code itself is instrumented with `ddtrace.auto` (agentless — Consumption-plan Functions have no agent sidecar) for APM, plus LLM Observability spans around the embedding calls in `index-search-shared`.

Operational telemetry must not serialize record arrays, workbook rows, provider bodies, connection strings, SAS tokens, or source query parameters.

## Investigate a run

1. Find the pipeline/activity run in Datadog's ADF Data Jobs Monitoring view, or `az datafactory pipeline-run query-by-factory`.
2. Follow the corresponding Function Activity's APM trace.
3. Confirm the `raw-data/` Parquet snapshot and `prepared-data/` JSON Lines object exist for that run.
4. Compare indexed document counts and sample narratives in Azure AI Search without logging full source data.
