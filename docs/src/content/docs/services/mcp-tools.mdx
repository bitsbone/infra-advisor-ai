The tool catalog is an evidence map. Choose the source whose scope matches the question; do not call several providers merely because they share a geography.

## Decision matrix

| User needs | Tool | Evidence boundary |
|---|---|---|
| Highway bridge condition or inspection indicators | `get_bridge_condition` | FHWA National Bridge Inventory; not real-time or non-highway structures |
| Federal disaster declaration history | `get_disaster_history` | OpenFEMA declarations; not current incident response or parcel risk |
| State generation, capacity, or fuel mix | `get_energy_infrastructure` | EIA historical/state energy data |
| Texas grid storage | `get_ercot_energy_storage` | ERCOT-specific storage data; not general national energy |
| Drinking-water compliance or Texas water-plan projects | `get_water_infrastructure` | EPA SDWIS or TWDB selected by query type |
| Texas traffic/construction open data | `search_txdot_open_data` | TxDOT datasets; not the NBI condition system |
| Internal project practices and indexed documents | `search_project_knowledge` | Azure AI Search project corpus |
| Produce a structured project document | `draft_document` | Template rendering from supplied facts; no retrieval |
| Open federal contracts and assistance opportunities | `get_procurement_opportunities` | Normalized SAM.gov and Grants.gov artifact |
| Historical federal awards and incumbents | `get_contract_awards` | USASpending award history; not open solicitations |
| State/local or broader web procurement context | `search_web_procurement` | Azure OpenAI web search; verify source recency and authority |

## Important selection distinctions

### Bridge versus TxDOT

Use NBI for structural condition and inspection fields. Use TxDOT for Texas traffic counts or construction/open-data questions. A Texas bridge question can need both, but only when the user asks for both condition and surrounding transportation activity.

### EIA versus ERCOT

Use EIA for comparable historical energy questions across states and fuel types. Use ERCOT for Texas grid-storage questions. Do not interpret one source's units or time resolution as the other's.

### Water source selection

`get_water_infrastructure` represents two evidence systems. Drinking-water system and compliance questions use EPA data; Texas planning-project questions use TWDB. The query type must make the intended source explicit.

### Opportunities versus awards

Open opportunities answer “what can we pursue?” Historical awards answer “who has won similar work?” For business-development research, awards often provide context before opportunity positioning. The .NET deterministic evaluator checks this order only when both tools were actually called.

### Search versus drafting

Search gathers evidence. Drafting formats supplied evidence into a known document shape. A safe chain is:

```text
search project/provider sources → inspect citations → draft document from selected facts
```

The drafting tool must not fill missing facts with plausible prose.

## Parameters and reference codes

Exact tool schemas, limits, enums, and defaults come from the live MCP `tools/list` response and the language implementations. This avoids copying large parameter tables that drift independently.

Some boundaries still require domain codes:

- NBI uses two-character state FIPS and three-character county FIPS codes.
- Procurement filters may use NAICS classifications.
- EIA fuel values and FEMA incident types must match the source contract.

Validate codes near the input boundary and preserve leading zeroes. Do not maintain a partial “complete code list” in prose; link or derive from the authoritative source.

## Multi-tool patterns

| Goal | Sequence | Why |
|---|---|---|
| Federal opportunity positioning | awards → opportunities → project knowledge | combines incumbent history, open work, and internal approach |
| Infrastructure risk brief | asset source → disaster history → project knowledge → draft | separates factual evidence from document formatting |
| Texas corridor context | bridge condition → TxDOT data | combines structure condition with traffic/project context |

Stop the chain when the user's question is already answered. More tool calls increase latency, failure surface, and the amount of external data entering the model context.

<ObservationChecklist title="Review a tool decision">

- The selected source actually covers the requested geography, asset, time range, and question type.
- Parameters use the provider's required code and unit conventions.
- The trace shows no redundant provider calls.
- The answer distinguishes source facts from agent inference.
- Citations or artifacts preserve safe official provenance.
- Empty or partial provider results remain visible instead of becoming invented certainty.

</ObservationChecklist>

<Aside type="caution">
Direct tool invocation through the authenticated sandbox bypasses agent selection but not the provider's data and privacy boundary. Treat its output as untrusted external data and never paste production credentials into arguments.
</Aside>
