# Lessons

- Every new feature must ship with public site documentation under `docs/src/content/docs`, including its application behavior, AI relationship, operational workflow, and observability story.
- Treat the repository as public educational material: never commit privileged secrets or real user data, and explicitly explain when a client-side identifier is designed to be public.
- Do not hard-wrap Markdown prose; keep each paragraph or list item on one physical line.
- A runnable example is incomplete without platform-specific prerequisites, install, run, test, configuration, and telemetry verification instructions.
- For Datadog iOS SDK 3.x network monitoring, configuring RUM `urlSessionTracking` is not sufficient: enable `URLSessionInstrumentation` for a concrete `URLSessionDataDelegate` class and create the session with that delegate; do not assume `URLSession.shared` is instrumented.
- Volley's default timeout is too short for many AI requests; use an explicit long timeout with zero automatic POST retries, preserve exactly-once telemetry completion, and classify timeout versus offline versus HTTP failures for the UI.
- For mobile Session Replay, use the platform-specific `maskSensitiveInputs`/`MASK_SENSITIVE_INPUTS` setting when the requested policy is `mask_sensitive_inputs`; document that it masks Datadog-classified sensitive fields rather than every editable field.
- For Datadog Mobile App Testing, never present an iOS `.xcarchive` as the upload artifact. Produce and validate a signed `.ipa` exported with Development (`debugging` in Xcode 26) or Ad Hoc (`release-testing` in Xcode 26) provisioning, and confirm the embedded provisioning profile before handing it off.
- A booted iOS Simulator window does not guarantee that .NET `mlaunch` will select it. Local MAUI run instructions must pass `-p:_DeviceName=:v2:udid=...`, verify the UDID through the active Xcode toolchain, and specify the simulator runtime identifier explicitly.
- Documentation components and page archetypes must remain composable guidance rather than a universal template. Choose the structure that best serves the topic, and use comparisons such as SDK versus OpenTelemetry only where they improve understanding.
- A documentation redesign is not a content migration until the prose itself has been audited against the implementation. After introducing navigation, metadata, or components, inspect every page for duplicated explanation, stale factual claims, unclear audience, and missing observable evidence; rewrite or remove content rather than merely wrapping it in a new presentation layer.
- Concise prose inside static cards is still a static documentation experience. Use an interactive component only when it lets the learner perform a meaningful action—follow a boundary, compare paths, inspect evidence, test recall, or record progress—and preserve an accessible text path for the same idea.
- Do not expose internal documentation-governance metadata as unexplained learner-facing badges. Terms such as "verified," "stable," or dated review markers imply guarantees a newcomer cannot interpret; communicate implemented behavior, limitations, and planned work directly in the surrounding prose.
- Preserve the user-approved product name during concept-driven redesigns; a visual concept or working title does not authorize renaming the application.
- A simulator launch target must build explicitly and fail fast before uninstall/install/launch; invoking an MSBuild `Run` target or continuing after a failed build can make a stale bundle look like the current implementation.
- After a .NET workload update, a missing `mono-aot-cross` path can come from stale target-specific `obj` metadata even when the replacement AOT pack is installed; clean the affected target and rebuild before repairing every workload.
- Do not combine an authenticated landing page, new-conversation configuration, and an active transcript into one visible state. Give each state one purpose, remove duplicate navigation controls, and explicitly normalize platform tab placement and control content alignment.
- A client action is not complete when only its side effect or telemetry succeeds; Copy, feedback, and report controls need visible pending/success/failure state, HTTP failures must not be swallowed, and generated launcher assets must be explicitly referenced by the packaged Android manifest.
- MAUI XAML compilation can accept an attached property that fails only when a deferred DataTemplate is instantiated on device. When a cross-platform crash occurs on history selection, use the captured RUM stack to identify the template line, remove platform-unsupported properties, and add a source guard plus device-level template smoke coverage.
- Persist mobile authentication only in platform-protected storage, restore observability identity with the session at startup, and clear both storage and Datadog identity on logout; never put a JWT in ordinary preferences or telemetry.
- Implement Datadog end-user feedback as `event_kind=feedback`, not an external evaluation: include an authenticated submitter, choose exactly one target, omit `join_on`, and do not imply that a Report signal creates a human-review ticket unless a separate workflow does so.
- Treat synthetic agent runs and asynchronous LLM judges as consumers of the same provider quota as interactive chat: make their volume configurable, sample optional evaluations, honor provider retry guidance, and return a distinct retryable error category when capacity is exhausted.
- A model-default change must update both backend configuration order and every client-side offline fallback; otherwise fresh sessions and degraded metadata requests silently select different models.
